# Промпти, якими керували ШІ

Увесь код написав агент Claude Code. Нижче — що йому давали і як він це трактував.

1. **Контекст:** файл завдання «Тусовка» та слайд із критеріями оцінювання (Безпека 40, Надійність 30, Якість 30; бонуси за тести, дизайн, деплой).
2. **Чекліст безпеки**, вставлений у промпт як обов'язкові вимоги:
   - атомарний запис на подію (транзакція + умова в запиті + унікальний ключ `(event_id, user_id)`), без овербукінгу навіть за 50 паралельних запитів;
   - криптостійкі токени запрошень, приватні події не потрапляють у список/пошук, перевірка `author_id` для кожної мутації;
   - обкладинки: ліміт 5 МБ, magic bytes (лише JPEG/PNG/WebP, жодних SVG), нове ім'я UUID;
   - бізнес-правила на бекенді: дата в майбутньому, місць 1–10 000, без запису на минулі події, не зменшувати місця нижче кількості учасників;
   - ліміти довжини, екранування XSS, `HttpOnly; SameSite=Lax` cookie;
   - bcrypt/argon2, секрети в `.env` + `.env.example`, без stack trace у відповідях;
   - інтеграційні тести однією командою з негативними сценаріями.
3. «Дизайн виглядає як з 2000-х, зроби сучасніше» (жовта гама — побажання).
4. «Уважно перевір усі умови в файлі» — самоаудит: перевірено запуск із чистого клону за README, знайдено й виправлено регістронезалежний пошук для кирилиці та надто жорсткий rate limit для спільного IP.
5. «Прогони по оцінюванню» — агент написав скрипт із 58 атак (IDOR, приватні події, гонка 18 користувачів × 2 запити на 2 місця, XSS, SVG/поліглоти/20 МБ, CSRF, open redirect, повтор cookie після виходу, брутфорс, зламані форми) і прогнав його на живому сервері; виправлено показ найновіших коментарів і керуючі символи в email.
6. Після загального рев'ю («Безпека: погано, Надійність: добре, Якість: середньо»): «перевір абсолютно все — щоб користувач не зайшов під адміном, щоб паролі зберігались і т.д.». Агент знайшов і закрив:
   - **ReDoS** у перевірці email: квадратична регулярка — 1 МБ у полі вішав потік сервера на години (тепер довжина перевіряється першою, регулярка лінійна);
   - слабкі паролі (`12345678`, `password`) — тепер потрібні літери + цифри, відсіюються популярні паролі;
   - розподілений підбір пароля з багатьох IP — ліміт на акаунт;
   - 500 на величезних числових ID, кешування HTML-сторінок, редиректи з керуючими символами;
   - автор більше не займає місце на власній події; сесії не злітають після перезапуску сервера;
   - підтверджено: ролі адміністратора немає взагалі (немає полів/маршрутів), паролі — лише Argon2id-хеші, які ніде не показуються.
